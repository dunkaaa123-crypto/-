# 영업관리(Sales Hub) — Firebase 배포 안내

회사 메일 + 비밀번호로 로그인하는 독립 웹사이트 버전입니다. 화면과 기능은 claude.ai 버전(`index.html`)과 같고, 로그인·데이터 저장만 Google Firebase로 바뀝니다.

- 로그인: 회사 메일 + 비밀번호. 처음 쓰는 사람은 **비밀번호를 만들고 메일 인증**을 해야 합니다(남의 메일로 가입하는 것 방지).
- 출입: 관리자가 **명단에 메일을 등록한 사람만** 들어올 수 있습니다.
- 권한(서버에서 강제): 명단·설정·로그인 허용 목록은 관리자(소유자·사업부장)만, 영업기회·활동은 본인 담당 건만 수정(팀장·사업부장은 전체 수정), 목표는 팀장·사업부장만 수정.
- 비용: 10여 명 규모는 Firebase 무료 요금제(Spark) 범위 안에서 운영될 가능성이 큽니다.

---

## 1단계. Firebase 프로젝트 만들기 (10분, 한 번만)

1. https://console.firebase.google.com 에 회사 구글 계정으로 로그인 → **프로젝트 추가** → 이름 예: `my-saleshub` → Google 애널리틱스는 꺼도 됩니다.
2. 왼쪽 메뉴 **빌드 › Authentication** → 시작하기 → **로그인 방법**에서 **이메일/비밀번호** 사용 설정 → 저장.
   - **템플릿** 탭에서 언어를 **한국어**로 바꾸면 인증·비밀번호 재설정 메일이 한국어로 갑니다.
3. 왼쪽 메뉴 **빌드 › Firestore Database** → 데이터베이스 만들기 → 위치 **asia-northeast3 (서울)** → **프로덕션 모드**로 시작.
4. 톱니바퀴 **프로젝트 설정 › 일반 › 내 앱** → 웹(</>) 아이콘 → 앱 이름 입력 → 등록. 화면에 나오는 `const firebaseConfig = { ... };` 블록 전체를 복사해 둡니다. (→ 3단계의 `FIREBASE_WEB_CONFIG`)
5. **프로젝트 설정 › 서비스 계정** → **새 비공개 키 생성** → JSON 파일이 내려받아집니다. 메모장으로 열어 내용 전체를 복사해 둡니다. (→ 3단계의 `FIREBASE_SERVICE_ACCOUNT`)
   - 이 파일은 관리자 열쇠입니다. 다른 사람에게 보내거나 저장소에 올리지 마세요.
6. **프로젝트 설정 › 일반**의 **프로젝트 ID**를 적어 둡니다. (→ 3단계의 `FIREBASE_PROJECT_ID`)

## 2단계. (도메인을 쓸 경우) 도메인 준비

- 회사 도메인의 하위 주소(예: `sales.회사도메인.com`)를 쓰려면 회사 IT(도메인 관리 담당)의 도움이 필요합니다. 5단계에서 Firebase가 알려 주는 DNS 레코드 두세 줄을 등록해 주면 됩니다.
- 도메인이 없으면 Firebase 기본 주소 `https://프로젝트ID.web.app` 으로 바로 쓸 수 있습니다.

## 3단계. GitHub에 비밀값 4개 넣기 (5분, 한 번만)

GitHub 저장소 → **Settings › Secrets and variables › Actions › New repository secret** 에서 아래 4개를 만듭니다.

| 이름 | 넣을 값 |
|---|---|
| `FIREBASE_PROJECT_ID` | 1-6의 프로젝트 ID (예: `my-saleshub`) |
| `FIREBASE_WEB_CONFIG` | 1-4에서 복사한 `firebaseConfig` 블록 전체 |
| `FIREBASE_SERVICE_ACCOUNT` | 1-5 JSON 파일 내용 전체 |
| `OWNER_EMAIL` | 소유자(관리자) 회사 메일. 여러 명이면 쉼표로 구분 |

## 4단계. 배포 (버튼 하나)

GitHub 저장소 → **Actions** 탭 → 왼쪽 **Firebase 배포 (영업관리 Sales Hub)** → **Run workflow** → Run workflow.
2~3분 뒤 초록색 체크가 뜨면 `https://프로젝트ID.web.app` 에서 열립니다. 화면을 고친 뒤에도 같은 버튼으로 다시 배포합니다.

## 5단계. 도메인 연결 (선택)

1. Firebase 콘솔 **빌드 › Hosting › 커스텀 도메인 추가** → `sales.회사도메인.com` 입력.
2. 화면에 나오는 **TXT / A 레코드**를 회사 IT에 전달해 DNS에 등록합니다. 확인되면 보안 인증서(https)가 자동으로 붙습니다(보통 몇 시간, 최대 하루).
3. **Authentication › 설정 › 승인된 도메인**에 같은 도메인을 추가합니다. (빠뜨리면 그 주소에서 로그인이 안 됩니다)

## 6단계. 첫 로그인과 명단 등록

1. 소유자가 사이트를 열고 **처음 사용(비밀번호 만들기)** → `OWNER_EMAIL`로 넣은 메일과 새 비밀번호 입력 → 메일로 온 인증 링크 클릭 → **인증 완료**.
2. **시스템 관리 › 조직·팀 설정**에서 사업부·팀 이름을 확인합니다.
3. **시스템 관리 › 사용자·권한 › 여러 명 한 번에 붙여넣기**에 `이름, 팀 이름, 역할, 회사메일` 순서로 붙여 넣습니다.
   ```
   홍길동, , 사업부장, owner@company.com
   김팀장, 영업1팀, 팀장, lead@company.com
   이대표, 영업1팀, 영업대표, rep@company.com
   ```
   명단의 이메일이 곧 로그인 허용 목록입니다. 이메일은 표에서 바로 고칠 수도 있습니다. 이상하면 **로그인 허용 목록 동기화** 버튼을 누릅니다.
4. 팀원에게 사이트 주소를 보내고 "처음 사용에서 비밀번호를 만들고 메일 인증을 하라"고 안내합니다. 로그인하면 명단의 이름·팀·역할이 자동으로 적용됩니다.

## 자주 묻는 것

- **인증 메일이 안 와요** → 스팸함을 확인하세요. 회사 메일 서버가 `noreply@프로젝트ID.firebaseapp.com` 을 막는 경우 IT에 허용을 요청하세요.
- **"명단에 등록되지 않은 이메일입니다"** → 관리자가 명단에 그 메일을 넣었는지, 오타가 없는지 확인하세요.
- **비밀번호를 잊었어요** → 로그인 화면의 **비밀번호 찾기**.
- **claude.ai 버전의 데이터는?** → 자동으로 넘어오지 않습니다. 명단·팀·단계 설정은 위 6단계로 다시 넣습니다.

## 파일 구성

| 파일 | 역할 |
|---|---|
| `../index.html` | 화면 소스 (claude.ai 버전과 공용) |
| `shim.js` | 로그인 처리와 Firebase 저장소 연결 |
| `auth.html` | 로그인 화면 |
| `firestore.rules.tmpl` | 서버 보안 규칙 (`OWNER_EMAIL`이 배포 때 들어감) |
| `build.py` | 위 파일을 합쳐 `dist/` 배포본을 만드는 스크립트 |
| `../.github/workflows/firebase-deploy.yml` | Actions 배포 버튼 |
